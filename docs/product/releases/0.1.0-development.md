# Development release review notes

These notes describe a review candidate, not a deployed or accepted customer release.
Product and release owners must approve the exact artifact, configuration and customer
actions before publishing. [Capability scope](../../generated/capability-catalog.md)
remains Preview/Experimental, with no new Production or Certified configuration.

## Users and tenant administrators

The Knowledge Center now includes return/refund, RF lot/serial, dock appointment, yard,
hold, sortation, loading, fixed-asset and expense instructions. Task help names the role,
prerequisites, expected saved state and recovery action. Curated user and tenant-admin
manuals are generated from those same topics; physical-device and customer acceptance
are still required for supported use.

The identity changes in the same development tree enforce the shared password policy
and revoke older sessions after relevant credential changes. Upgrading from a build
without credential-version claims requires users to sign in again. Privileged recovery
and recovery-destination changes follow the current security workflow; administrators
must use authorized roles and keep recovery reasons/evidence. Review the actual release's
migration and training plan before applying these changes to a customer.

## Integrators and implementation teams

The canonical generated API document is now under `docs/api/generated/`; its prior
path is retained as a generated compatibility projection. This documentation relocation
does not introduce new public endpoint scope. The data dictionary now includes scoped
development metadata, physical keys and report/sensitive-field registries. Compare it
with the target tenant and approved migration mapping before import.

## Migration, rollback and remaining limits

The additive identity migrations in this development tree have been used locally;
this note does not assert production application. Plan session invalidation, backup,
schema/binary compatibility and business smoke checks using the
[upgrade/rollback procedure](../../operations/upgrade-and-rollback.md).

Mixed-owner warehouse production, physical RF/mobile acceptance and regulated audit
evidence retain their Stage 47 gates. Provider, legal, retention and customer UAT claims
require their own scoped evidence. Preserve legacy documentation and screenshots until
their reviewed replacement and transition requirements pass.
