## Stage 13 — Master Blueprint Functional Scope ✅ (2026-07-13 → 17)

Closed the gap between the strong backend/kernel (Stages 1-12) and an actually usable business app. Grouped into 5 phases by risk/effort; every item shipped as its own commit, live-verified on a throwaway instance first.

### Phase A — Security
- [x] **13.1 Security response headers** — HSTS/CSP/X-Frame-Options/X-Content-Type-Options via one `securityHeaders` middleware wrapping the whole mux.
- [x] **13.2 Feature-flag route gating** — new `featureGate()` wrapper; wired to the 3 seeded flags (oms/wms/forecasting). Fails closed if a flag can't be confirmed enabled.
- [x] **13.3 MFA (TOTP)** — stdlib-only (`crypto/hmac`+`sha1`+`base32`), required for HR/Admin. Login routes an MFA-required role into enrollment or challenge via a short-lived purpose token.
  - **Bug fixed**: the purpose token initially didn't carry `tenantID`, silently blanking tenant scoping for the whole MFA flow.

### Phase B — Frontend for existing backend logic
- [x] **13.4 POS billing screen** — pure frontend against the already-working availability/checkout APIs.
- [x] **13.5 Finance/GL screen** — read-only trial balance view.
- [x] **13.6 Fulfillment/reservation workbench** — status-driven task actions.
  - **Bug fixed**: the location filter only checked a field literally named `location`; `FulfillmentTask` actually stores `location_code` — non-admins got zero results. Fixed with a `COALESCE`.
- [x] **13.7 Marketplace settlement screen** — settlements + logistics bookings.
  - **Bug fixed (deeper case of 13.6's bug)**: doctypes with *no* location field at all (`MarketplaceSettlement`/`LogisticsBooking`) were also silently hidden from non-admins, since `COALESCE(NULL,NULL) = 'HO'` is never true in SQL. Fixed to also allow the `IS NULL` case through.

### Phase C — The structural gap
- [x] **13.8 Maker-checker approval engine** — `engines/approval.go`, amount-slab → role routing (PurchaseOrder pilot: <50k Store Manager, 50k+ HR/Admin). Enforces maker≠checker, role match, and location match on every decision. Reused by nearly every later approval-gated feature.
  - Re-approval-on-edit: editing an Approved document resets it to Pending Approval automatically.

### Phase D — Functional module breadth
- [x] **13.9 Vendor/Customer masters** — registered as real Master doctypes, full generic CRUD for free.
- [x] **13.10 GST/Tax engine** — CGST/SGST/IGST split calculation (calc-only; e-invoice/IRN explicitly out of scope, no GSP credentials).
- [x] **13.11 Report catalog** — Current Stock, Sales Register, Vendor Ledger, Payables Ageing.
- [x] **13.12 RFQ / vendor quote comparison** — quote comparison list + one-transaction winner selection (auto-rejects the rest, closes the RFQ).
- [x] **13.13a HR Foundation** — Employee/Attendance/Leave, access-link sync (deactivating an Employee blocks their linked login), payroll export.
  - **Bug fixed**: Leave approve/reject buttons sent a partial payload to an update endpoint that replaces the whole document — every approval failed validation. Fixed to resubmit the full record.
- [x] **13.13b Fixed Asset Management** — capitalize → depreciate (straight-line, calculated live not stored) → transfer → dispose, posting real balanced GL entries.
  - **Bug fixed**: a disposed asset's register still showed full original cost as net block instead of zero.
- [x] **13.13c Expense Management** — claim → verify → pay, reusing the approval engine. Date-window + duplicate-bill checks on create.
  - **Bug fixed**: Cashier had create-but-not-update access, so a Cashier who filed their own claim had no way to submit it.
- [x] **13.13d CRM/Loyalty (scoped MVP)** — append-only point ledger, earn at checkout / burn via a separate redeem endpoint. No campaigns/segmentation/vouchers.
- [x] **13.13e Manufacturing (scoped MVP)** — single-level BOM + linear Production Order (Draft → Material Issued → Completed), reuses the existing inventory floor-check. No routing/MRP/QC.

### Phase E — Ops/scale hardening

  - **Bug fixed**: lockout expiry compared a Postgres UTC timestamp against Go's local (IST) clock — a genuinely-expired lock looked ~5.5 hours in the future. Fixed by doing the whole comparison in SQL against Postgres's own clock.
  - Inbound Shopify webhook HMAC signature verification added.
- [x] **14.25 Containerization** — built, then **reverted** on explicit request (standing no-Docker policy). `promote.ps1`/`manage.ps1 -Env` remains the one real deployment path.

## Stage 44 — Per-tenant hostnames (`<client>.wholeops.in`) ✅ (opened + built 2026-08-14, **live-verified in production 2026-09-13**)

Opened because the user registered **wholeops.in** (Hostinger, 2026-08-14) and asked for a URL scheme of `clientbrandname.wholeops.in` with the module after the hostname. Checking that against the code first found **the scheme did not exist on either axis**, and that is recorded here rather than quietly building something adjacent:

- `apiMiddleware` never consulted the `Host` header at all. Tenant came from `X-Tenant-ID`, then `?tenant_id=`, then `"default"`, and after login from the bearer token's own claim. One hostname served every tenant.
- The SPA routes on `location.hash` (`public/app.js`), so the module segment is `#oms`, not `/oms`.

**Scope decision (2026-08-14):** the host→tenant half is built now because it is what makes per-client addresses real. The `/module` path half is **not** built — see 44.6.

- [x] **44.1** `public.tenants.host_slug` — `db/migrations_stage44_tenant_host_slug.sql`, additive, applied and verified on the dev DB. Backfilled from `tenant_id` **only where `tenant_id` is already a legal DNS label**: `tenant_id` is free-text `VARCHAR(100)` with no character restrictions and this repo's own fixtures contain `_`, which is illegal in a hostname. Verified: `default` → `default`, `tenant_new` → `NULL` (correctly skipped — a blind backfill would have minted a slug that could never be served, and the failure would only have shown up as an unexplained certificate error much later). Unique index on `LOWER(host_slug)` because hostnames are case-insensitive; partial, so any number of tenants may keep a NULL slug.
- [x] **44.2** Host→tenant resolution attached at the **one** choke point every request already passes (`apiMiddleware`, per CLAUDE.md's shared-choke-point rule) — `internal/server/tenant_host.go`. `<slug>.<TENANT_BASE_DOMAIN>` now precedes `X-Tenant-ID`/`?tenant_id=` in the pre-auth chain, on the reasoning that a hostname had to survive DNS and a certificate to arrive whereas those two are simply whatever the caller typed. Single label only: a two-level name would need a wildcard certificate Let's Encrypt will not issue over HTTP-01, so accepting one would produce a tenant that resolves but can never be served. Reserved labels (`app`, `www`, `api`, `admin`, `sandbox`, `mail`, …) never resolve to a tenant, so provisioning a client called "www" cannot take over that hostname.
- [x] **44.3** **The token stays authoritative, and a mismatch is refused.** A session for tenant A presented on tenant B's hostname returns the same generic 401 as any dead session rather than being silently served as A. This is deliberately *not* "host wins" — letting the host override the claim would have been a real cross-tenant escalation. It is the narrower guarantee: the claim still scopes every query, and the hostname merely has to agree with it.
- [x] **44.4** CORS widened by *shape*, not by list — `originAllowed()`. `CORS_ALLOWED_ORIGINS` still wins first and is unchanged; the addition is that https origins at the base domain or one label under it are accepted, so provisioning a tenant no longer needs an app restart with a longer allowlist. Scoped tight: https only, no port, no path, same single-label rule. The suffix test is anchored on `"." + base` so a domain someone else registers that merely ends in the same letters (`acme.evilwholeops.in`) is not mistaken for ours — locked by a test.
- [x] **44.5** **On-demand TLS, gated by the app** — `deploy/Caddyfile` + `GET /internal/tls-ask`. Per-tenant hostnames are not listed in the config (the tenant set changes without a config change), so each certificate is obtained on its first TLS handshake. The `ask` gate is what makes that safe: Caddy asks the app before requesting a certificate and proceeds only on a 2xx, so a hostname that is not a live tenant never reaches Let's Encrypt. Without it anyone who pointed a DNS record at this box could drive unbounded issuance. **Deliberately achieved without `xcaddy`** — a wildcard certificate would need a DNS-01 provider plugin and therefore a custom Caddy binary to keep patched, which is exactly the trade 26.1.3a already rejected. Found and fixed during validation: current Caddy **removed** `on_demand_tls`'s `interval`/`burst` throttle, so `ask` is now the only gate — which is why the handler fails closed on every path (unset `TENANT_BASE_DOMAIN`, unknown slug, reserved label, DB-less startup all answer non-2xx). Proxy behaviour moved into an `(erp_app)` snippet imported by both site blocks so the platform host and tenant hosts cannot drift. `/internal/*` is refused on the public listener; Caddy reaches the gate over 127.0.0.1, which never passes through that block.
- [x] **44.10** **Unknown tenant hostnames are refused (`tenantHostGate`, 2026-08-15).** A single-label, non-reserved name under `TENANT_BASE_DOMAIN` that matches no tenant now gets a 404 instead of falling through to `X-Tenant-ID` and then `"default"` — which is what `nosuchclient.wholeops.in` did until now: it served the default tenant's login page. **Opened by 26.1.3b, not by 44.5.** While per-tenant certificates come from the ask gate, an unknown hostname never completes a handshake, so the fall-through was unreachable; behind Cloudflare the origin serves one wildcard certificate for every name under the base domain and the gate stops filtering anything, so the app has to make the judgement itself. Not a security boundary — the token claim scoped every query before this and still does — it is the product guarantee that a per-client address means a client. Attached to the whole-mux wrapper chain in `routes.go` rather than to `apiMiddleware`, because the SPA shell and static files are what a browser asks for first and they never pass through that middleware; inside `securityHeaders` so the 404 still carries them. Inert without `TENANT_BASE_DOMAIN`, locked by a test that asserts localhost/loopback/apex/platform-host/foreign-domain all still pass through.

A 404 maps to `GLOBAL-0004`, which carries `LogRequired`, so every probe at a random subdomain would have written a Medium row to the system-error log — a log-flood vector, since sweeping subdomains is exactly what scanners do. It now writes through `writeResponse` directly: the same envelope every other error uses (that function is the single place bodies are written), without the catalog's logging hooks.

## Stage 45 — User-reported batch: UI/UX design-bar sweep, round 1 ✅ (opened + built 2026-08-19; **live-verified 2026-08-31**)

Eight gaps the user reported directly against the live `:8080` deployment while screenshotting through Financial Accounting, PIM, HRM and Setup, plus the "no one has ever seen / brainless-intuitive" design-bar ask that reframed them as instances of a repeatable rubric rather than one-off fixes. Frontend-only — `public/app.js`, `public/styles.css`, `public/index.html`. No Go changes, no migration, no new dependency.

- [x] **45.1** **Duplicate panels on Vendor Invoice / Payment Proposals / Bank Reconciliation.** Root cause was a re-entrancy gap in the shared router, not anything view-specific: `renderView()` (app.js) cleared `#view-root` and showed a placeholder synchronously, then `await`ed the view's own fetch before appending its header/panel — so a second call fired before the first one's fetch resolved (double-click, or any duplicate trigger) would clear the first call's placeholder but not stop the first call from still appending its content afterwards, landing both calls' output side by side, permanently. Fixed with a `viewRenderToken` counter: each call renders into a **detached scratch container**, and only swaps it into the live `#view-root` if its token is still current when its fetch resolves — a stale call's content is discarded outright instead of ever touching the visible DOM. The existing Chromium sticky-header-caching workaround (`requestAnimationFrame(() => root.offsetHeight)`) and the `translateDOM` sweep moved from `renderViewContent` into `renderView`'s token-gated `finally`, since both need to run against the real root post-swap, not the scratch container. Affects every one of the ~45 views dispatched through this router, not just the three that happened to get screenshotted.
- [x] **45.2** **Module tab bars (PIM/Finance/Reports/HR/Manufacturing) silently clipped instead of scrolling.** `.page-container` is `overflow-x: hidden`, and each module's tab-bar row (`tabBar.style.display = 'flex'`, no wrap, no scroll of its own) is a bare unwrapped flex row — so at a narrow enough width/zoom (reported: 90%), trailing tabs (e.g. PIM's "Supplier Submissions") weren't just hard to find, they were **unreachable through the UI**, with no scrollbar, no wrap, and no recovery path short of resizing the window or knowing the direct URL. Fixed by giving each of the 5 tab-bar rows its own `overflow-x: auto`, scoped to the row rather than widening `.page-container`'s own overflow behaviour (which risked introducing a page-wide horizontal scrollbar for unrelated wide content elsewhere).
  - **The first version of this fix was verified live and found to make it worse: the tab bar collapsed to `height: 0`, fully invisible.** `.page-container` is a `flex-direction: column` container; `overflow-x: auto` alone suppresses a flex item's automatic min-height (content-based sizing only applies when overflow is `visible`, and per the CSS Overflow spec the *used* value of the other axis becomes `auto` regardless of what's declared) — so whenever the page's other content was tall enough to overflow vertically, the tab bar had nothing stopping it shrinking to nothing. **Fixed with `flex-shrink: 0`**, which exempts the item from shrinking at all rather than trying to win the automatic-minimum-size calculation. `overflow-y: visible` was added alongside it on the theory that it would stop the axis-pairing rule from firing — **live measurement disproved that theory** (`getComputedStyle` still reports `overflow-y: auto` even with `visible` explicitly declared); it's harmless and documents intent but `flex-shrink: 0` is what's actually doing the work. Re-verified live after the correction: normal width unchanged, narrow width shows a real non-zero-height scrollable bar (measured 46px, vs 0px before) with "Supplier Submissions" reachable by scroll.
- [x] **45.3** **Setup-prerequisite banner is no longer dismissible.** The yellow "This screen needs some setup first" banner previously had an × that dismissed it for the rest of the browser session (`sessionStorage`) — a deliberate Stage 41 design choice at the time, but the user asked for it to go further: as long as the prerequisite is genuinely unmet, the banner should show on every visit, full stop.
