# Projects and service requirements

Intended behavior drafted from the existing backlog. This does not claim availability. See the [capability catalog](../../generated/capability-catalog.md) for scoped maturity and [PRD core](../product-requirements.md) for shared rules.

## FR-SRV-001

**Engagement scope.** Identify customer, agreement/project, entity, owner, scope and budget before collecting costs/work.

Acceptance: Unauthorized cross-project access and unapproved scope changes fail.

## FR-SRV-002

**Work and billing.** Link time, material, expense, milestone and service completion to an approved billable outcome.

Acceptance: Duplicate time/billing and cancelled requests cannot inflate revenue.

## FR-SRV-003

**Resolution and margin.** Expose response/resolution clock, next action and reconciled project margin.

Acceptance: Reopened cases and late costs remain traceable; dashboards state period and cost basis.

The process owner validates the outcome; QA executes the scenarios. [Traceability](../../generated/requirements-traceability.md) identifies implementation/test/help locations. Open Stage work: 37.7, 37.8. A test file is not signed execution evidence.
