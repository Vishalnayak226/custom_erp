Settings and configuration #

These are the screens under Settings that change how the whole business works. Most need an Admin; Extension Hooks needs a Super Admin. Users, roles and approval rules have their own handbook: Security and approvals.

Configuration #

What it is

One screen for every operational setting, one module at a time: return windows, match tolerances, cycle-count intervals, session length and more.

Why it matters

A change takes effect at once, everywhere, with no restart and no code change. Numbers outside their allowed range are refused, so a typing slip cannot stop the system.

Use case

The owner allows returns for 45 days instead of 30. The admin opens Sales & Returns, sets the sales return window to 45 and saves. The next return at any store uses 45 days.

How to do it

  1. Open Settings → Configuration.
  2. Pick the module on the left.
  3. Change the values you need.
  4. Click Save Changes.

A setting you never changed shows its default. Credentials and Data governance in the same menu open their own parts of this screen.

Stores #

What it is

Every store, warehouse and HO in one list, each on its own page. These are the same Location records as Setup → Location; there is no second list.

Why it matters

A purchase order is refused when its billing store has no State and its legal entity has no GSTIN or State (PURCHA-4965). The list flags those stores No State, so they are fixed before anyone raises a PO there.

Use case

A buyer's PO at a new store is refused. The admin opens Settings → Stores, picks the No State view, opens the store, chooses Karnataka under Address & GST and clicks Save store. The PO now saves.

How to do it

  1. Open Settings → Stores.
  2. Click a store's code to open its page, or New Store to add one.
  3. Fill in the sections. Legal entity is required.
  4. Click Save store.

A red No State marks a store a purchase order would refuse. From legal entity means the store takes its State from its legal entity. Opened from a purchase order (Edit store or Open store), saving goes back to it.

Data quality #

What it is

A queue of master-data problems: customers sharing a phone or email, vendors sharing a GSTIN or a name, items with the same name, and records with missing or wrong tax details.

Why it matters

Duplicates split a customer's history and loyalty, and wrong tax details end up on invoices and GST returns. The queue finds them before they cost money.

Use case

Two cashiers created the same customer with the phone 98200 12345. The scan lists both records. The admin merges them in CRM; the next scan marks the problem Fixed.

How to do it

  1. Open Settings → Data quality.
  2. Click Scan now.
  3. Open each record and correct it.
  4. Click Scan now again: corrected problems become Fixed.
  5. To accept a problem as it is, click Ignore and give a reason.

A scan never adds a problem twice. A Fixed problem that comes back is opened again; an Ignored one stays ignored until you click Reopen.

Data Healer #

What it is

A heal is a one-time fix that brings records made before a release up to what the new release expects. Data Healer lists every heal and whether it is waiting or done.

Why it matters

A release never changes your data by itself. A heal shows you every change before it runs, and it runs only once.

Use case

After a release, items need a short alias for labels. A strip above every screen says a heal is waiting. The admin opens it, types over two of the suggested aliases, and clicks Run heal. The strip goes away.

How to do it

  1. Click Fix now on the strip, or open Settings → Data Healer.
  2. Open the waiting heal.
  3. Check the value each record will get; type over any you want different.
  4. Click Run heal.

While a heal waits, the records it covers cannot be saved from their screen. Users who cannot run it see Ask your admin. Done is final. Full detail: Data Healer.

Prefix Configs: document numbers #

What it is

The number series behind every document: purchase orders, bills, transfers, items and the rest.

Why it matters

Each store and each financial year gets the numbers your accounts and auditors expect, without anyone typing them.

Use case

The Pune store (Short Code PUN) wants its own run of bill numbers. The admin edits the sales bill series, sets Store in the number to Yes and Restart numbering to every financial year, checks the preview and saves. Pune's next bill carries PUN and starts again at 1 each April.

A new number series: prefix, length, when it restarts, and how the next number looks

How to do it

  1. Open Settings → Customize → Prefix Configs.
  2. Pick a group beside New Series to narrow the list.
  3. Click Edit on the series.
  4. Set the prefix, separator, number length, suffix, Restart numbering, the year and Store in the number; the preview shows the next number.
  5. Click Save.

Full detail: Admin Guide §B.3.2.

Dynamic Labels #

What it is

Your own words for the system's labels, for example "Design Number" where the app says "SKU".

Why it matters

Staff see the words of their own trade, so screens need less training.

Use case

A jewellery business calls a brand a "Collection". The admin adds a rule from Brand to Collection; every screen shows Collection from then on.

How to do it

  1. Open Settings → Customize → Dynamic Labels.
  2. Click Add Translation Rule.
  3. Enter the label exactly as it shows now, then your word.
  4. To undo, click Remove on the rule.

The change shows the next time a screen opens.

Extension Hooks #

What it is

Lets a developer you hire be told when something happens in the ERP, such as a document being saved, without access to the database.

Why it matters

Your own systems stay in step with the ERP while it stays closed to them. The call log shows every call, so a missing update is easy to trace.

Use case

A developer's app needs every new vendor. The Super Admin registers a hook on Vendor with the developer's https:// address. Next day the developer says one vendor never arrived; View Log shows that call and the error their server sent back.

How to do it

  1. Open Settings → Customize → Extension Hooks.
  2. Choose the hook point and record type, enter the https:// address and a timeout, and click Register Hook.
  3. Click View Log to see a hook's last 100 calls.
  4. To stop a hook, click Delete.
  5. To give a developer a short-lived token, open Settings → Customize → Extension tokens, pick the record type and minutes (at most 1440), click Issue Token and copy it: it is shown once.

API access #

What it is

The keys an outside system uses to call the ERP's API: an API key or an OAuth client, each limited to the scopes it needs.

Why it matters

Each system gets its own key with only the access it needs. You can see its calls, change its secret, or cut it off without affecting anyone else.

Use case

A courier partner needs to read orders. The admin issues a key with only the order scope and sends the secret once. Months later the partner changes staff, and the admin clicks Rotate to issue a new secret.

How to do it

  1. Open Settings → Customize → API access.
  2. Click + New API access, name it and tick only the scopes it needs.
  3. Click Issue and copy the secret: it is shown once.
  4. Use Rotate for a new secret, Revoke to stop it, and Recent calls to see its traffic.

Full detail: API authentication.

Subscription #

What it is

Your plan, when the paid period ends, this month's use against what the plan includes, and the GST invoice for each payment.

Why it matters

You can see whether the account is paid up and how much of the plan you use before anything stops working.

Use case

The accountant needs last month's invoice for input tax. The admin opens Subscription and reads the GST invoice for that payment under Invoices: taxable amount, CGST and SGST or IGST, and the total.

How to do it

  1. Open Settings → Customize → Subscription.
  2. Read the status, plan and period end at the top.
  3. Check this month's use against the plan.
  4. Find each payment's GST invoice under Invoices.

Only an Admin sees this screen, and nothing on it changes the plan; plans are chosen and paid with the platform owner. Full detail: Your Subscription.

System Status #

What it is

What is running where: the latest deployment in each environment, the deployment history, and the backup and restore-drill history.

Why it matters

Answers "what version is live?" without logging in to the server, and shows when nobody has tested a restore for too long.

Use case

Before a store opening the admin checks that the last restore drill is recent. It shows a warning badge, so they ask the operator to run one before the weekend.

How to do it

  1. Open Settings → Monitoring → System Status.
  2. Read Latest Deployment by Environment.
  3. Open Settings → Monitoring → Backup history and check for a warning badge. Deployment history lists every deployment.

The screen is read-only. Rows appear only when the deploy and backup scripts record them, so an empty table means the scripts have not run against this database.
